Basic AI Flow

English · 日本語 · text guide

One AI workflow for backend (Go), admin (Next.js) and mobile-app (Flutter). Run it from the ai-flow-demo root, one stage at a time, always stopping for your approval.

The one command

CommandWhat it does
/aiflow PROJ-XXXXRuns the next stage of the ticket, then stops. A new ticket starts at stage 1.
/aiflowBoard of every ticket: stage, route, repos, next step.
/aiflow PROJ-XXXX statusProgress, plus time / tokens / estimated cost per stage.
/aiflow PROJ-XXXX featureNew-development ticket (feature/… branch) instead of a bug fix.
/aiflow PROJ-XXXX redo specRedo a stage (ticket spec plan impl review deliver).
/aiflow analyze · /aiflow wikiRefresh the knowledge graph (free) · write the architecture wiki (costs tokens).
/aiflow <PR/MR URL>Review an existing PR/MR.

6 stages

1 · TicketRead Notion, bug vs feature, affected repos, triage, branch
you approve
2 · SpecRoot cause or design
you approve
3 · PlanTDD tasks, one repo each
full only · you approve
4 · ImplementPer task: implementer + spec review + quality review
5 · ReviewFinal review across repos + test cases
full only
6 · DeliveryTests, manual QA, Draft PR/MR per repo, CI-review fixes, then Ready
QA + you approve

light 1 → 2 → 4 → 6, only when: one repo, 3 files or fewer, no API/schema/DB change, root cause located, it is a bug, not a sensitive area (billing, auth, migration). Stages 1 and 2 run in one turn with one approval.

full Everything else runs all six stages. The route is only upgraded, never silently downgraded. Each stage stops; read the output, then run /aiflow PROJ-XXXX again.

Output lives in docs/aiflow/<ID>/: ticket.md, spec.md, plan.md, reviews/, test-cases.md, status.md (progress, the only file used to pick the next stage) and log.json (time, tokens, cost).

Mandatory rules

Never push directly to mainChanges reach a base branch only through a PR/MR. No commits on develop/main, no force-push.
Never commit secretsKeys, tokens, passwords, .env* and credentials files are never staged or pushed; git diff --cached is checked before every commit.
Every write to GitHub/GitLab asks firstThat is git push, creating or editing a PR/MR, and posting a comment. The agent shows the action, the target and the exact text, and acts only on a clear yes. An earlier approval, the QA answer or a config flag never covers it. It never merges, approves or closes a PR/MR on its own.
Name the reviewerEvery review and approval records human:<name> or ai:<role> (<model>) in reviews/*.md, status.md approvals and PR comments.
One ticket branch everywhereWhile a ticket is open, the wrapper and every affected repo are on the same bug/PROJ-XXXX/… or feature/PROJ-XXXX/… branch.

PR/MR template

The title carries the Notion task ID, e.g. [PROJ-123] …, so the PR links to the task. The body keeps the team headings in Japanese.

HeadingContent
概要What this PR changes and why; links to related PRs and the spec/plan/review.
スクリーンショットBefore/after images if the UI changed; otherwise state there is no UI change.
相談項目Points to ask the reviewer, including Minor findings; なし if none.
動作確認手順How it was verified so the reviewer can repeat it: device, steps, result. Say what was not tested.

Delivery order (stage 6)

1. Run each repo's tests
2. QA gate           → "checked, create the PRs" (not consent to push)
3. Confirm           → push <branch> of <repo> to origin?
4. Confirm           → create the PR/MR as a DRAFT (title, base ← head, full body)
5. CI review runs    → run /aiflow <ID> again: fix or answer every CI comment
                       (each push / reply asks first), until none is open
6. Confirm           → mark Ready for review → the customer reviews
7. Merge             → only when you ask for it in chat

Source repos use gh (GitHub, base develop/main); the wrapper uses glab (GitLab, base main).

Updating the flow

Skills and rules come from the generic harness-ai-flow bundle. Change them there (with its README), then re-install here with install.sh --force; edits under .claude/skills/ are overwritten. Project-specific settings live only in aiflow/workflow.yaml.

Optional: aiflow-visual is a browser companion (local page for mockups and diagrams); stages offer it only for visual questions and only after you agree. Telemetry is off; keep .superpowers/ out of git.
