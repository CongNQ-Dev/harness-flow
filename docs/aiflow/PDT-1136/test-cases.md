# テストケース: PDT-1136 — 検索アクセス数のシーズン帰属修正

> 対象ブランチ: `bug/PDT-1136/fix_search_access_season_attribution`
> 環境: ステージング (iOS stage 3.17.0 以降 / Android stage 3.17.0 以降)
> 作成日: 2026-07-28

---

## 1. 前提条件 (Setup)

- ステージング環境のアプリがインストールされていること（iOS または Android）
- テスト用アカウントでログイン済みであること
- **複数シーズンが存在する作品**（例: シーズン1・シーズン2・シーズン3 以上）が検索できる状態であること
- 急上昇ランキングの計上を確認するため、管理画面またはAPIモニタリングツールで `UpsertSeasonSearchCount` の呼び出しログを確認できる権限があること（任意: ログ確認できる場合に限る）
- テスト前に、対象作品の各シーズンの検索カウントを把握・記録しておくこと（管理画面で確認）

---

## 2. テストケース A — シーズン2以降を検索から再生した場合に正しく計上される（主要修正の確認）

### 手順

1. アプリ下部のタブバーから「**検索**」をタップする
2. 検索バーに、複数シーズンある作品の**シーズン2以降のシーズン名**（例:「〇〇 シーズン2」）を入力して検索を実行する
3. 検索結果一覧に表示された**シーズン2**の作品カードをタップする
4. 作品詳細画面が表示されたら、最初のエピソードまたは任意のエピソードの「**再生**」ボタンをタップして再生を開始する
5. 再生が開始されたことを確認したら、再生を停止または終了する
6. 手順 2〜5 を、急上昇ランキングに反映されるために必要な回数（目安: 10回以上）繰り返す
7. アプリ下部のタブバーから「**ホーム**」または「**ランキング**」画面に移動する
8. 「**急上昇**」ランキングセクションを確認する

### 期待結果

| ステップ | 期待される結果 |
|---------|--------------|
| 1 | 検索タブが表示される |
| 2 | 検索結果にシーズン2の作品が表示される |
| 3 | シーズン2の作品詳細画面が開く |
| 4 | 動画再生が開始される |
| 5 | 再生が停止される |
| 6 | 各回の再生が正常に完了する |
| 7 | ホームまたはランキング画面に遷移する |
| 8 | **急上昇ランキングに「シーズン2」が表示される（シーズン1ではなく）**。管理画面またはログで確認した場合、`UpsertSeasonSearchCount` がシーズン2のIDで呼ばれていること |

**合否判定:**
- PASS: 急上昇ランキングにシーズン2（検索・再生したシーズン）が表示される
- FAIL: 急上昇ランキングにシーズン1が表示される（修正前の不具合が再発している）

## 3. テストケース B — シーズン3以降でも正しく計上される（シーズン数が多い作品での確認）

### 手順

1. アプリ下部のタブバーから「**検索**」をタップする
2. 検索バーに、複数シーズンある作品の**シーズン3**（またはそれ以降）のシーズン名を入力して検索を実行する
3. 検索結果一覧に表示された**シーズン3**の作品カードをタップする
4. 作品詳細画面が表示されたら「**再生**」ボタンをタップして再生を開始する
5. 再生が開始されたことを確認したら、再生を停止または終了する
6. 手順 2〜5 を、急上昇ランキングに反映されるために必要な回数繰り返す
7. 「**急上昇**」ランキングセクションを確認する

### 期待結果

| ステップ | 期待される結果 |
|---------|--------------|
| 1〜6 | テストケース A と同様 |
| 7 | **急上昇ランキングに「シーズン3」（検索・再生したシーズン）が表示される**。シーズン1およびシーズン2には誤って計上されていないこと |

**合否判定:**
- PASS: 急上昇ランキングに正しいシーズン（シーズン3以降）が表示される
- FAIL: シーズン1またはシーズン2が誤って急上昇ランキングに表示される

## 4. テストケース C — `X-Bump-Season-Id` ヘッダーなし（後方互換性の確認）

> このテストケースはネットワークプロキシ（Charles Proxy / mitmproxy など）を使って `X-Bump-Season-Id` ヘッダーを除去できる環境で実施すること。環境がない場合はスキップ可。

### 手順

1. プロキシツールを使って、アプリから送信される `X-Bump-Season-Id` ヘッダーをすべてのリクエストから除去するルールを設定する
2. アプリ下部のタブバーから「**検索**」をタップする
3. 検索バーに作品名（シーズン1のみの作品または複数シーズンある作品）を入力して検索を実行する
4. 検索結果の作品カードをタップし、「**再生**」ボタンをタップして再生を開始する
5. 再生が開始されたことを確認したら、再生を停止または終了する
6. 手順 3〜5 を繰り返す
7. 「**急上昇**」ランキングセクションを確認する

### 期待結果

| ステップ | 期待される結果 |
|---------|--------------|
| 1 | プロキシルールが正常に設定される |
| 2〜6 | 正常に検索・再生できること（ヘッダー除去により動作がクラッシュしないこと） |
| 7 | ヘッダーがない場合でも、`work.MainSeasonID`（= シーズン1相当）で正しく計上され、アプリがクラッシュしないこと |

**合否判定:**
- PASS: ヘッダーなしでも急上昇ランキングへの計上が動作し、アプリがクラッシュしない
- FAIL: アプリがクラッシュする、または計上が全く行われない

## 5. テストケース D — 検索以外の流入では計上されない（既存動作の維持確認）

### 手順

1. アプリ下部のタブバーから「**ホーム**」をタップする
2. ホーム画面上のバナーやカルーセルから、複数シーズンある作品の**シーズン2**の作品カードをタップする（検索タブは使わない）
3. 作品詳細画面が表示されたら「**再生**」ボタンをタップして再生を開始する
4. 再生が開始されたことを確認したら、再生を停止または終了する
5. 手順 2〜4 を繰り返す
6. 「**急上昇**」ランキングセクションを確認する（または管理画面でログを確認する）

### 期待結果

| ステップ | 期待される結果 |
|---------|--------------|
| 1〜5 | 正常に再生できること |
| 6 | **ホーム経由での再生はランキングに計上されない**（検索アクセスとしてカウントされない）。管理画面で確認した場合、`UpsertSeasonSearchCount` が呼ばれていないこと |

**合否判定:**
- PASS: ホーム経由の再生が急上昇ランキングに計上されない
- FAIL: ホーム経由の再生が急上昇ランキングに計上される

## 7. 不具合の再現確認 — 修正前の不具合が解消されていること

> このセクションは修正前に発生していた不具合が再現しないことを確認するためのものです。

### 修正前に発生していた不具合の概要

シーズン2以降のシーズンを検索・再生しても、急上昇ランキングにシーズン1が誤って計上されていた。

### 手順（不具合が再現しないことの確認）

1. アプリ下部のタブバーから「**検索**」をタップする
2. 検索バーに、複数シーズンある作品の**シーズン2**のシーズン名を入力して検索を実行する
3. 検索結果一覧に表示された**シーズン2**の作品カードをタップする
4. 作品詳細画面が表示されたら「**再生**」ボタンをタップして再生を開始する
5. 再生が開始されたことを確認したら、再生を停止または終了する
6. 手順 2〜5 を、急上昇ランキングに反映されるために必要な回数繰り返す
7. 「**急上昇**」ランキングセクションを確認する

### 期待結果（不具合が解消されていることの確認）

| ステップ | 期待される結果 |
|---------|--------------|
| 1〜6 | 正常に検索・再生できること |
| 7 | 急上昇ランキングに**シーズン2が表示され、シーズン1は表示されない**こと（修正前は誤ってシーズン1が表示されていた） |

**合否判定:**
- PASS: シーズン2を検索・再生した場合、急上昇ランキングにシーズン2が表示される（不具合解消）
- FAIL: 急上昇ランキングにシーズン1が表示される（不具合が修正されていない）
